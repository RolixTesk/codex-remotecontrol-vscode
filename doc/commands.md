# 命令说明

本文描述 Codex Live Remote 0.1.2 的实际实现。VS Code 中按 `Ctrl+Shift+P`，输入 `Codex Remote` 查找命令。

## 插件命令总览

| 命令 | 命令 ID | 具体效果 | 适用时机 |
|---|---|---|---|
| 启用 / 更新接入 | `codexRemote.enable` | 部署 wrapper/CLI，备份并修改 User 级 CLI 设置，定位当前官方 Codex binary | 首次接入、官方扩展升级后 |
| 连接当前项目 | `codexRemote.connect` | 定位原后端，按需启用其临时 Remote，等待连接就绪 | 已完成接入后的日常连接 |
| 配对手机 | `codexRemote.pair` | 按需连接 Remote，再请求配对码、生成并打开私有配对页 | 首次添加手机或重新配对 |
| 查看连接状态 | `codexRemote.status` | 读取原后端的 Remote 状态，更新状态栏 | 判断连接是否正常 |
| 断开当前项目 | `codexRemote.disconnect` | 关闭所选原后端的临时 Remote | 结束手机连接、切换窗口 |
| 恢复接入前配置（卸载前） | `codexRemote.restore` | 将 User 级 CLI 设置恢复到启用前的值 | 停用或卸载接入 |

“接入”表示官方插件后续通过 wrapper 启动 Codex；“连接”表示已有 Codex 后端连接 Remote；“配对”表示手机取得原生 Remote 授权。这三步分别处理启动入口、运行连接和手机授权。

## 启用 / 更新接入

此命令执行以下操作：

1. 查找已安装的官方 `openai.chatgpt` 扩展，确认对应架构的 Linux Codex binary 可用。
2. 将现有 wrapper 和 Python CLI 部署到 WSL 的 `~/.local/share/codex-remotecontrol/vscode/`。
3. 更新受管理配置中的官方 binary 路径，使用 `bridge` 模式。
4. 保存启用前 `chatgpt.cliExecutable` 的 User / Global 值，将该设置改为稳定 wrapper 路径。

设置写入 User / Global 层，适用于读取这一设置的窗口，并非只修改当前项目。Windows 本地窗口要求官方 Codex 设置已启用通过 WSL 运行；Remote-WSL 在 Linux 侧部署和调用后端。

**完成结果：** 状态栏显示“等待重载”。等当前任务结束，手动运行 **Developer: Reload Window**，再打开原 Codex 聊天。运行中的旧进程继续使用它启动时的入口；新配置在下次启动后端时生效。

**重复执行：** 若 User 设置仍指向本插件的稳定 wrapper，更新保留已有恢复备份；可用它刷新官方扩展升级后的版本路径。若曾恢复或改用其他 CLI 后再次显式启用，会保存此次启用前的设置。

此命令配置启动入口；手机连接和配对分别通过对应命令完成。日常已接入的窗口只需运行 **连接当前项目**。

## 连接当前项目

此命令根据项目目录查找已接入 wrapper、已在官方 UI 加载的聊天，以及该聊天实际持有写锁的原 Codex 后端。

多根工作区要求先选择项目。同一项目对应多个后端时，要求明确选择 PID；多个聊天由同一个后端管理时可以直接选择该后端。

如果 Remote 已关闭，命令向原后端发送临时启用请求；如果正在连接或已经连接，则读取并等待连接状态。连接状态等待上限为 45 秒，后端调用本身另有超时。它复用原进程和聊天，不启动第二个 Codex 后端。

**完成结果：** 状态栏显示“已连接”，并显示成功通知。“已连接”表示该后端与 Remote 通道连接就绪，不等于手机已配对或当前在线。手机应在 ChatGPT 的 Codex / Remote 中选择此主机的同一聊天。

**作用范围：** Remote 开关影响整个所选后端进程。当前桌面聊天和任务继续运行，手机经原生 Remote 操作同一后端。

**重复执行：** 已连接的后端会保留连接，不会重新请求配对码。另一个可见后端正在连接或已连接时，本命令拒绝静默切换；先在原窗口运行 **断开当前项目**。

## 配对手机

此命令与连接命令使用相同的项目和后端选择逻辑。Remote 未连接时先完成连接，然后调用原生配对接口，请求手动配对码并生成私有页面。

**完成结果：** 默认浏览器尝试打开配对页，VS Code 显示“配对页已生成”通知。页面包含手动码；安装可选 `qrcode` 依赖后，也可生成二维码。配对数据和页面保存在 Linux 私有目录，页面标有有效期。

在手机 ChatGPT 中完成配对、选择此主机，再打开桌面的同一聊天。页面生成只表示配对请求已发出，手机确认后才完成授权。

通知中的 **打开配对页** 按钮会再次打开同一页面，不重新请求配对码。浏览器未打开时，可按提示手动打开已经生成的页面；关闭通知不会断开 Remote。

**重复执行：** 每次运行命令都会重新请求配对码并更新页面。已有配对的日常使用应运行 **连接当前项目**。

## 查看连接状态

此命令定位原后端，读取 Remote 状态，更新状态栏及项目/PID 提示信息。点击状态栏等同于运行此命令。

它属于查询操作，不会启用或关闭 Remote，也不会创建配对码。如果当前后端有本地配对记录，CLI 还会尝试查询该配对是否已被手机认领；插件状态栏主要显示 Remote 连接状态。

状态栏是**最近一次操作或查询的结果**，没有持续轮询。要判断当前状态，请重新运行查询。

| 显示 | 含义 | 下一步 |
|---|---|---|
| 未查询 | 插件刚激活，尚未读取连接状态 | 运行查看状态 |
| 等待重载 | 接入设置已写入，需要下次启动后端生效 | 等任务结束后重载 |
| 已连接 | 上次查询返回 `connected` | 手机可选择主机；必要时完成配对 |
| 未连接 | 上次查询返回 `disabled` | 需要手机连接时运行连接命令 |
| `connecting` 或其他原始状态 | 后端尚未就绪或返回了其他状态 | 查询状态并按提示处理 |
| 操作未完成 | 上一次命令报错 | 阅读错误提示；查询状态确认实际结果 |
| 接入配置已恢复 | User 级 CLI 设置已还原 | 等任务结束后重载 |

## 断开当前项目

此命令向所选原后端发送临时关闭 Remote 请求，并确认状态变为 `disabled`；已经关闭时直接返回当前状态。

**完成结果：** 状态栏显示“未连接”，手机与此后端的 Remote 通道关闭。桌面聊天和正在执行的任务继续运行，wrapper 接入设置保留。

此命令不执行撤销手机配对授权的接口。下次使用已有配对时，重新运行 **连接当前项目** 即可；它也不承担停止当前 Codex 任务或恢复 CLI 设置的作用。

关闭影响整个后端进程，包括该后端管理的其他聊天。切换到另一个后端前，先断开原后端。

## 恢复接入前配置（卸载前）

此命令读取接入前的备份，并检查当前 User / Global `chatgpt.cliExecutable` 是否仍等于插件管理的 wrapper 路径。若已被其他操作更改，命令报错并保留当前值。

**完成结果：** 原值为字符串或 `null` 时恢复该值；原设置不存在时移除该 User 设置。状态栏显示“接入配置已恢复”。

等当前任务结束后重载窗口，新后端按恢复后的配置启动，再卸载配套插件。恢复值是当时保存的值：若启用前已有实验 wrapper，也会恢复那个 wrapper，并不一定直接恢复官方 bundled Codex。

此命令只恢复 CLI 设置，不调用断开接口，也不删除已部署后端、备份或配对文件。运行中的进程继续使用原启动入口，直到窗口重载或关闭。需要马上结束手机连接时，先运行 **断开当前项目**。

## 进度任务和通知

0.1.2 将后台操作与通知交互分开：后台请求返回后，进度任务结束、操作锁释放。保留成功或失败通知、暂不选择配对页按钮，都可以继续执行下一条命令。

后台请求或项目/PID 选择仍未结束时，重复运行命令会提示“已有 Codex Remote 操作正在执行，请等待结果”，不会再发送一次操作。

若旧版在后端已连接后仍卡住，可以关闭该命令的成功/错误通知释放旧等待；加载 0.1.2 补丁需要在任务结束后重载窗口。写操作超时或报错后，先查询状态确认结果，再决定后续操作。

## CLI 命令

在 WSL 终端运行。已安装短入口时使用 `codex-remote`；否则可直接调用已部署 CLI：

```sh
python3 ~/.local/share/codex-remotecontrol/vscode/scripts/remote.py --help
```

| 命令 | 具体效果 |
|---|---|
| `codex-remote list` | 查询可访问的已加载聊天，输出 `childPid`、`threadId`、`workspace`、`active`；默认列出所有项目 |
| `codex-remote connect` | 为当前目录对应的原后端连接 Remote，效果与插件连接命令相同 |
| `codex-remote pair --open` | 按需连接并生成配对页，尝试打开浏览器；不带 `--open` 时只生成页面并输出路径 |
| `codex-remote status` | 查询当前目录对应的原后端状态；可能附带 `pairingClaimed` 或配对过期/不可用提示 |
| `codex-remote disconnect` | 为当前目录对应的原后端关闭 Remote，保留桌面任务和接入设置 |

`list` 按聊天输出，一个 PID 可能有多行；`active` 表示该聊天当前有活跃 turn。它只发现可访问的 wrapper 实例，不等于系统全部 Codex 聊天。

CLI 的常用参数：

| 参数 | 效果 |
|---|---|
| `--workspace <目录>` | 明确项目目录；操作命令默认当前目录，`list` 默认不限定目录 |
| `--pid <PID>` | 明确原后端；同项目存在多个后端时操作命令必须指定 |
| `--open` | 仅用于 `pair`，打开已生成的私有配对页 |

示例：

```sh
codex-remote list --workspace /你的项目目录
codex-remote connect --workspace /你的项目目录 --pid 12345
codex-remote status --workspace /你的项目目录 --pid 12345
codex-remote disconnect --workspace /你的项目目录 --pid 12345
```

示例 PID 需要替换为 `list` 返回的当前值。PID 在窗口重开后可以变化。CLI 成功返回退出码 `0`；业务错误返回 `1`；参数错误由参数解析器返回 `2`。配对页生成成功但浏览器未打开时，仍返回 `0`，并提示手动打开页面。

CLI 不提供修改 VS Code 设置的启用/恢复命令；这两项使用插件入口。

## 常见提示

| 提示 | 含义与处理 |
|---|---|
| 请先运行“启用 / 更新接入” | 稳定后端文件或配置尚未部署完整，先完成接入，再空闲重载 |
| 此项目没有已加载的 Codex 聊天 | 没有找到此项目可访问的 wrapper/thread；打开原聊天，并检查接入是否已经重载生效。提示不代表官方历史聊天不存在 |
| 此项目有多个 owner | 同项目存在多个原后端；在插件中选择，或在 CLI 中指定当前 PID |
| 另一个窗口已连接 Remote | 先在原窗口断开，再连接目标窗口 |
| 所选聊天的原 owner 已变化 | 原进程或聊天状态发生变化；重新查询列表，不使用旧 PID |
| 当前 cliExecutable 已被其他操作更改 | 恢复命令保留当前外部设置，需按实际配置处理 |
| 配对页已生成，浏览器未打开 | 按提示手动打开页面；已有配对请求，无需因此重复配对 |

日常连接不会自动重连。窗口关闭或重载后，需要打开聊天并再次连接。官方扩展升级后运行 **启用 / 更新接入** 更新 binary 路径，再在空闲时重载。
